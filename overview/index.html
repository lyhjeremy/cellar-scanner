Cellar Scanner
Label in, grounded profile out

Local OCR, grounded retrieval and a fine-tuned grape classifier

A 1.5B model tuned on a laptop names the grape from a blind note

Cellar Scanner reads a wine label with local OCR and Claude, retrieves similar wines from 30,000 Wine Enthusiast reviews, and keeps only the sentences it can ground in those reviews. Its Blind Taste Mode runs a Qwen2.5-1.5B model, LoRA fine-tuned with MLX on Apple Silicon, that guesses the grape from a tasting note with the grape name masked out: 27.7% Top-1 across 40 varieties, against 8.7% for the untuned base model and 23.0% for Claude prompted zero-shot.

The LoRA model is ahead of Claude on Top-1 by 4.7 points. Because Claude's 200 notes are a subset of the LoRA model's 300, the two can be compared note by note: on those 200, the LoRA model was right on 55 (27.5%) and Claude on 46 (23.0%). Of the 67 notes only one of them got right, the LoRA model took 38 and Claude 29, and an exact sign test puts that split at p = 0.33. It is a lead that sampling noise could erase. The macro-F1 gap (0.253 against 0.119) is wider, which says the LoRA model's hits are spread across more varieties. Claude is ahead on Top-3 (30.5% against 27.7%).

The LoRA model's Top-1 and Top-3 are identical because it never fills ranks 2 and 3. Its training target was the single line "1. {variety}", so it learned to give one answer and stop. A retrain with three-item targets would let it use the extra guesses.

Making the task blind

Masking the grape name, and three bugs found by running it

Many reviews name the grape outright ("this Cabernet shows..."), which would turn blind tasting into string matching. A regex masks each variety name and its common synonyms before training and scoring; it fired on 20.1% of the 41,389 rows, and the rate is written to eval/masking_report.json.

The dataset keeps the 40 varieties with at least 500 reviews, caps each at 1,200, and splits by wine title so no wine appears in both train and test (37,289 train, 2,076 validation, 2,024 test; the leakage check in eval/dataset_card.json passed).

Three numbers looked wrong during the build, and each was a bug. The first index build reached a third of its 30,000 target until a water-filling allocation replaced a flat per-variety quota. Claude first scored below the untrained base model because markdown-wrapped answers failed an exact string match; answers are now matched against the class list. And the first benchmark read the test file in order and covered only 6 of 40 varieties; a seeded shuffle fixed it (40 of 40 in the 300-row subsample) and changed the headline result.

The training run

800 iterations on a laptop

The adapter was trained with mlx_lm.lora on the 4-bit Qwen2.5-1.5B-Instruct: 12 layers, batch 4, 800 iterations, learning rate 1.5e-4, sequence length 768. That is 3.96M trainable parameters (0.256% of the model), 3,200 training examples seen, and a peak of 4.4 GB of memory. Validation loss fell from 3.895 at the start to 1.154 at iteration 600 and finished at 1.196.

The scanner

From a label photo to a cited profile

tesseract reads the label locally. One claude -p call checks that the photo is a wine label and extracts a structured card (producer, grape, vintage, region). The card queries a Chroma index of 30,000 reviews, embedded with sentence-transformers and sampled across every represented variety. A second Claude call writes a profile and pairings from the retrieved reviews, and a token budgeter records what went into that prompt.

  1. Domain gateA photo that is not a wine label gets a refusal, and no card is made up for it.
  2. Field validationVintage is range-checked; the grape is validated against the winemag vocabulary.
  3. Claim groundingEach sentence of the profile and each pairing reason must match a retrieved review; the rest are dropped and the answer regenerates. Every citation is the id of a retrieved review.
  4. Confidence gateA low-confidence read asks for a retake.
  5. Semantic cacheRe-scanning the same bottle returns the cached answer; the hit rate shows in the dev panel.

Limitations

What the numbers do not show

The LoRA-versus-Claude gap on Top-1 is within sampling noise (sign test p = 0.33 on the 200 notes both saw). The LoRA model cannot rank a second or third guess. Training saw 3,200 of the 37,289 training rows; whether a longer run would help is untested here. The labels are the dataset's variety field, which mixes grapes with blends and styles (Red Blend, Rosé, Port), so some "errors" are arguable.

There is no hosted demo: the app is a Gradio interface run locally with python app.py. Label reading depends on OCR quality; when the read is weak, the confidence gate asks for a retake.
